# Raafat Sys | نظام شركة رأفت

نظام إداري عربي لشركة رأفت للدعاية والإعلان والتجارة العامة.

> مشروع مستقل تماماً عن raafat-map-live.

## الأقسام
- لوحة التحكم والتقارير
- العملاء (حالات العملاء والبحث والفلترة)
- الباقات الإعلانية وتحويل IQD/USD بسعر الصرف من الإعدادات
- المواقع الإعلانية
- الحملات مع اختيار العميل والباقة والمواقع والدفعات
- مالكو الأسطح وعقاراتهم ومساحاتهم
- عقود إيجار الأسطح، الأقساط، المعاينة والطباعة والتجديد برقم RA-1 وما بعده
- إعدادات سعر الصرف

## التشغيل
هذا تطبيق ويب ثابت، افتح `index.html` بخادم محلي، أو انشر المستودع على GitHub Pages (Settings → Pages → Deploy from branch → main / root).

التطبيق يبدأ بوضع **معاينة تجريبية** ببيانات خيالية في الذاكرة فقط؛ البيانات المدخلة هنا تزول عند تحديث الصفحة ولا يتم إرسالها إلى خادم.

## ربط قاعدة البيانات الآمنة
1. أنشئ مشروع Supabase **جديداً لهذا النظام**.
2. نفّذ `supabase/schema.sql` مرة واحدة من SQL Editor بعد مراجعته.
3. من Authentication → Users أنشئ مستخدم موظف (لا تفتح التسجيل العام).
4. بعد إنشاء المستخدم، أضف معرّف المستخدم في جدول `staff_members` بدور `admin` من SQL Editor:
   `insert into public.staff_members(user_id, role) values ('USER_UUID', 'admin');`
5. من شاشة ربط النظام أدخل **Project URL** و**publishable/anon key فقط**، ثم سجّل دخولك بالبريد وكلمة المرور.
6. لا تضع أبداً `service_role` أو مفتاح secret في الواجهة أو GitHub.

## حماية البيانات
- كل الجداول بنظام Row Level Security ولا يمكن تصفحها دون مستخدم مفعل ضمن staff_members.
- صور البطاقة في bucket خاص `identity-cards` مع سياسات وصول للموظفين المفعلين، وليست عامة.
- وضع المعاينة لا يخزّن هواتف أو أرقام بطاقات حقيقية.
- سعر الصرف يغيّر **العرض المحوّل** فقط، ولا يعيد كتابة العقود التاريخية.
- إنجاز التشغيل الإنتاجي يتطلب ربط مشروع Supabase واختبار الصلاحيات والنسخ الاحتياطي قبل إدخال بيانات حقيقية.

## حدود النسخة الأولية
توفير الواجهة وعمليات CRUD الأساسية وربط الجداول؛ يلزم اختبار الإنتاج على قاعدة بيانات خاصة بالمشروع بعد اختيار إعدادات الاستضافة والبريد والصلاحيات.
